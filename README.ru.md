# bit

[English](README.md) · **Русский**

**bit** — системный язык программирования, построенный вокруг одной идеи:
**простой контроль над компьютером — из коробки.**

Файлы и папки, процессы, сеть, память и терминал — часть самого языка: никаких пакетов,
обёрток и настройки. Программа, которая обходит папку, запускает инструмент и пишет отчёт, —
это несколько простых строк:

```
host {
    dir logs = "logs";
    do(logs >> make);
    file report = logs >> file("report.txt");

    string who = "whoami" >> run;                 # команда оболочки
    mas cmd = ("git", "status", "--short");       # программа с аргументами, без оболочки
    string changes = cmd >> run;

    do(report >> write("пользователь: {who}\n") >> append(changes));
    print("{os >> host}: ядер {os >> cpus}, отчёт в {report >> name}");
}
```

Компилятор написан на самом bit, собирается с нуля (без C, без LLVM) и переводит код
прямо в машинный — через системные `as` и `ld`.

---

## Философия

1. **Контроль над системой — из коробки.** Работа с системой встроена в язык и читается простыми
   словами: `f >> read`, `d >> list`, `"example.com" >> ping`, `cmd >> run`, `mem >> take(16)`,
   `os >> procs`. Одна программа собирается под macOS, Linux и Windows.
2. **Видно, что меняет мир.** *Значение* просто считается; *действие* (запись в файл, отправка
   в сеть, присваивание) оборачивается в `do(...)`, а присваивание — это `ch` (change). Читая код
   сверху вниз, всегда видно, где меняется состояние.
3. **Сбой решаешь ты.** Сорвавшаяся системная операция по умолчанию завершает программу, но внутри
   `recover { } else { }` программа решает сама: пропустить, повторить, записать в отчёт, выбрать код
   выхода.
4. **Компилятор проверяет то, что можно доказать.** Он отклоняет неверные типы, чтение пустых
   переменных и индексы, для которых не удалось доказать диапазон. При доступе к массиву также
   проверяется его текущая длина. Время жизни выделенной памяти `bytes` определяет программа.
5. **Имена не надо угадывать.** `shift_left`, а не `shl`; `host { }`, а не `fn main() {}`.
   У bit свой небольшой словарь (`do`, `ch`, `>>`, `keep`, `each`) вместо конвенций C, C++ и Rust.
6. **Вся цепочка своя.** `bitc.bit` собирает сам себя и выдаёт ассемблер ARM64 или x86-64.

## Собрать компилятор

Нужны системные `as` и `ld` (на macOS — Command Line Tools, на Linux — binutils).

```bash
./bootstrap.sh
```

Соберёт `./bitc` из ассемблерных семян в `bootstrap/` и проверит, что компилятор
воспроизводит сам себя.

## Собрать и запустить программу

```bash
./bitc run hello.bit              # собрать во временный файл и запустить
./bitc build hello.bit -o hello   # собрать исполняемый файл
./bitc asm hello.bit              # напечатать ассемблер
./bitc run prog.bit -- арг1 арг2  # передать программе аргументы
```

Другие цели:

```bash
./bitc build hello.bit -o hello.exe --os windows    # нужен x86_64-w64-mingw32-gcc
./bitc build hello.bit -o hello --os linux          # собирать asm на Linux-машине
./bitc build hello.bit -o hello --arch x86_64       # x86-64 на ARM-маке (через Rosetta)
```

## Быстрый тур

```
host {
    num x = 152;                    # целое
    dec p = 1.5;                    # дробное
    string s = "Привет";            # текст, " или '
    bool ok = true;

    do(x >> ch(x + 1));             # присваивание — действие

    mas a = (5, 3, 9, 1, 7);
    print("больше 4: {a >> keep(it > 4)}");    # (5, 9, 7)
    print("вдвое: {a >> each(it * 2)}");       # (10, 6, 18, 2, 14)
    print("сумма: {a >> sum}, есть 9: {a >> has(9)}");

    for i in 0:4 {                             # 0..4 включительно
        print("a[{i}] = {a >> get(i)}");       # границы доказаны компилятором
    }

    file f = "заметки.txt";
    recover {
        print(f >> read);
    } else {
        print("не прочитал: {term >> error}");
    }
}
```

Больше программ — в [`examples/`](examples/): файлы, память, сеть, система.

## Состояние

bit поддерживает системные утилиты, обработку текста, структуры, словари, функции как значения
и многофайловые программы через `use`. Рабочая папка и окружение управляются через `term`;
запускаемые программы наследуют их. Есть `read_only`, права POSIX, удаление дерева папок
и обход с метаданными `FileInfo`. Для текста есть `find`, `contains`, `upper`, `lower`,
`code`, `char`, `pad` и `repeat`; числа печатаются как `hex` или `fixed`-текст; массивы
сортируются по любому ключу `num` или `string`, а `map` обходится по ключам в порядке
добавления. Сетевой сервис может слушать заданный IPv4-адрес,
узнавать адрес клиента через `peer` и измерять интервалы через `os >> clock`.
TCP-подключение можно ограничить по времени (`connect(мс)`),
а вид пойманной ошибки даёт стабильный код через `term >> error_code`.
Целевые платформы — macOS (arm64 и x86-64), Linux (x86-64)
и Windows (x86-64). Сообщения компилятора и среды выполнения пока на русском.

## Устройство репозитория

| Путь | Что это |
|---|---|
| `bitc.bit` | компилятор на bit (лексер, парсер, проверка типов и доказательства, генерация кода) |
| `rt/` | среда выполнения в ассемблере: `arm64.s`, `x86_64.s` и сгенерированные версии для Linux и Windows |
| `tools/` | `embed_rt.bit` (встраивает среду в компилятор), генераторы среды для Linux и Windows, `build_opt.sh` (экспериментальная оптимизирующая сборка в `build/`) |
| `bootstrap/`, `bootstrap.sh` | ассемблерные семена и сборка с нуля с проверкой самосборки |
| `tests.sh`, `tests/` | тесты (примеры и проверки ошибок) на arm64 и x86-64; `tests_win.sh хост` — их прогон на живой Windows по SSH; `tests_win.sh --stack-check хост` дополнительно проверяет выравнивание стека при вызовах |
| `examples/` | примеры программ |
| `docs/` | документация на английском (`*.md`) и русском (`*.ru.md`) |
