## Философия: do и ch

bit — про **простой контроль над компьютером из коробки** и про то, чтобы было видно, что программа
делает. Нет скрытых перегрузок, неявных преобразований и спрятанных эффектов, поэтому язык
различает две вещи:

- **значение** — то, что вычисляется: `2 + 2`, `a >> get(0)`, `mem >> free`;
- **действие** — то, что меняет мир: запись в файл, отправка в сеть, **присваивание переменной**.

Любое действие оборачивается в `do(...)`, а само присваивание записывается как `ch` (change):

```
num x = 10;
do(x >> ch(x + 1));     # теперь x = 11
```

Так в коде всегда видно, где просто считают, а где меняют состояние. `do` и `ch` — часть языка
намеренно: это подпись под каждым изменением, а не «шум».

## Основы синтаксиса

- **Комментарии** начинаются с `#` и идут до конца строки.
- **Строки** — в двойных `"..."` или одинарных `'...'` кавычках.
- **Интерполяция**: `{выражение}` внутри строки подставляет значение. Сама скобка — `{{` и `}}`.
- **Экранирование**: `\n` (перевод строки), `\r` (возврат каретки), `\t` (табуляция), `\\`, `\"` и `\'`. Последовательности работают и в строковых выражениях внутри интерполяции.
- **Числа**: `152`, `-7`, шестнадцатеричные `0xFF`, дробные `1.5`.
- **Инструкции** заканчиваются `;`.
- **Блоки** функций, `if`, `else if`, `else`, `for`, `while` и `recover` можно открыть
  двоеточием. Тело начинается на следующей строке и пишется с отступом. Возврат к отступу
  заголовка завершает блок. Старый синтаксис с `{ ... }` также поддерживается.
- **Точка входа** — блок `host { … }`. С него начинается программа; функции `main` нет.

```
host {
    string кто = "мир";
    print("привет, {кто}!");        # привет, мир!
    print("скобка: {{ не интерполяция }}");
}
```

В `for i in 0:3:` первое двоеточие задаёт диапазон, второе открывает блок. Ветви
`else if` и `else` в синтаксисе с двоеточием выравниваются по заголовку `if` или `recover`.

```
fn sum_to(num limit):
    num total = 0;
    for i in 0:limit:
        do(total >> ch(total + i));
    return total;

host {
    if sum_to(3) == 6:
        print("совпало");
    else:
        print("ошибка");
}
```

## Типы

| Тип | Что хранит | Пример |
|---|---|---|
| `num` | целое число (64 бита) | `num x = 152;` |
| `dec` | дробное число | `dec p = 1.5;` |
| `string` | текст (UTF-8) | `string s = "Привет";` |
| `bool` | `true` / `false` | `bool ok = true;` |
| `mas` | массив значений одного вида | `mas a = (1, 2, 3);` |
| `bytes` | кусок сырой памяти | `bytes b = mem >> take(16);` |
| `file` | путь к файлу | `file f = "data.txt";` |
| `dir` | путь к папке | `dir d = "logs";` |
| `conn` | сетевое соединение | `conn c = "host:port" >> connect;` |
| `server` | слушающий сокет | `server s = net >> listen(9100);` |
| `proc` | чужой процесс | см. [proc](#proc-чужие-процессы) |
| `all` | тип выводится из значения | `all n = a >> get(0);` |

`all` — «определи сам»: компилятор подставляет настоящий тип из правой части.

## Объявление переменных

```
num x = 152;              # с начальным значением
num e();                  # пустая — читать нельзя, пока не присвоишь
all s = add(2, 3);        # тип выводится из вызова

string g = "глобальная";  # объявленная вне функций — глобальная
mas names = (string);     # пустой массив строк (вид в скобках)
mas a = (1, 2, 3);        # массив с элементами
mas b(3) = (10, 20);      # с лимитом вместимости 3
mas c = ();               # пустой; вид выведется из первого add
```

Пустая переменная (`num e();`) заводится без значения: компилятор не даст её прочитать, пока в неё
не положат данные через `ch`:

```
num e();
do(e >> ch(x * 2));       # теперь читать можно
```

Объявления вне функций — **глобальные**, видны во всех функциях.

## Цепочки и it

`>>` передаёт значение слева направо — читается как «затем». Цепочку можно продолжать сколько угодно:

```
mas top = a >> sort >> get(3:4);                 # отсортировать, затем взять срез
num n = path >> open >> append("x\n") >> sz;
```

Если цепочка-действие присваивается переменной, `do` не нужен — объявление само его оборачивает:

```
mas even = nums >> keep(it % 2 == 0);      # объявление, do не нужен
do(c >> add(7) >> add(8));                 # чистое действие, нужен do
```

`it` — текущий элемент в методах массива (`keep`, `each`):

```
a >> keep(it > 4)          # оставить элементы больше 4
a >> each(it * 2)          # заменить каждый на удвоенный
```

## Операторы

- **Арифметика**: `+` `-` `*` `/` `%`
- **Сравнения**: `==` `!=` `<` `>` `<=` `>=`
- **Логика**: `and` `or` `not`
- **Диапазон**: `a:b` — от `a` до `b` включительно (в `for`, в срезах, в `input`)
- **Биты** — методы, а не значки: см. [num и dec](#num-и-dec).

```
print("{x / 3}, остаток {x % 7}");
if x > 100 and ok { print("да"); }
for i in 0:4 { ... }           # 0, 1, 2, 3, 4
s >> get(0:5)                  # символы с 0 по 5
```

## Управление

```
if x > 100 and ok {
    print("большое");
} else {
    print("маленькое");
}

for v in a {                   # по элементам массива
    do(sum >> ch(sum + v));
}

for i in 0:4 {                 # по диапазону (включительно)
    print(a >> get(i));
}

num k = 0;
while k < 3 {
    do(k >> ch(k + 1));
}
```

`thread имя { ... }` запускает второй поток программы и даёт ему имя. Блок исполняется
на своём стеке, не дожидаясь главного хода, а `do(имя >> wait)` ждёт его завершения:

```
num total = 0;

host {
    thread work {
        do(total >> ch(42));
    }
    do(work >> wait);
    print(total);
}
```

После `wait` системные ресурсы потока освобождаются. Несколько потоков могут ждать один и тот
же поток; повторный `wait` уже завершённого и ожидавшегося потока сразу возвращается.
Потоки, которые больше не нужны, следует дождаться: до этого их ресурсы сохраняются.

Тело потока видит глобальные переменные и функции программы; локальные переменные
объемлющей функции ему недоступны, поэтому всё общее записывается глобально.
Потоки идут одновременно, поэтому общий изменяемый ресурс защищают одним замком:

```bit
lock guard;
num total = 0;

fn increment() {
    do(guard >> enter);
    do(total >> ch(total + 1));
    do(guard >> leave);
}

host {
    thread a { do(increment()); }
    thread b { do(increment()); }
    do(a >> wait);
    do(b >> wait);
    print(total);                    # 2
}
```

`enter` ждёт, пока замок освободится, и занимает его; `leave` освобождает. Замок можно
передать параметром типа `lock`, а `lock other = guard;` создаёт ещё одно имя того же
замка. Все обращения к общим данным должны использовать один и тот же замок, включая чтение.
`leave` должен выполнять поток, который вызвал `enter`; не занимай один замок повторно
в том же потоке и не жди под замком поток, которому нужен этот замок. Нарушения этих
правил могут привести к зависанию или неопределённому поведению.

Замок не освобождается автоматически при `return`, `break` или сбое, перехваченном
через `recover`: освобождай его явно на каждом пути. Созданный замок хранится до конца
программы, поэтому для повторной работы переиспользуй его, а не создавай в цикле.

У каждого потока свои обработчики `recover` и свой текст последней ошибки, поэтому сбой в одном
потоке никогда не попадает в обработчик другого. Поток, у которого нет своего обработчика,
сообщает об ошибке и завершает программу — так же, как это сделал бы главный ход.

`pick` выбирает ветку по значению выражения. Значения пишутся прямо, в одной ветке их может
быть несколько через запятую, а `else` срабатывает, если не подошло ничего. Провалов нет,
поэтому `break` не нужен, а значение вычисляется один раз:

```
pick status {
    200 { print("ок"); }
    301, 302 { print("переехало"); }
    else { print("другое: {status}"); }
}
```

`pick` работает с `num` и `string`. Каждая ветка открывает свою область видимости, как любой блок.
`break` внутри `pick` относится к объемлющему циклу, а не к выбору.

`break` выходит из ближайшего цикла, `next` переходит к его следующей итерации:

```
for v in a {
    if v == 0 { next; }        # пропустить и дальше
    if v > 100 { break; }      # выйти из цикла
    do(sum >> ch(sum + v));
}
```

## Функции

```
fn fib(num n) {
    if n < 2 { return n; }
    return fib(n - 1) + fib(n - 2);
}

fn add(num a, num b) {
    return a + b;
}

fn show(mas m) {
    print("элементов {m >> sz}");
}
```

Параметры — `тип имя` через запятую. `return` возвращает значение. Функция без `return` ничего
не возвращает и вызывается через `do(...)`, если это действие.

## Структуры, словари, функции как значения

`record` объявляет структуру. Конструктор принимает значения в порядке полей. `p >> x` читает поле,
`do(p >> x(7))` меняет его. Присваивание создаёт второе имя той же записи, а `ch` заменяет привязку.
Поле может иметь конкретный тип, ранее объявленный тип структуры или тип коллекции, например
`mas(string)` и `map(num)`.

У `map` строковые ключи и один тип значений. `set` добавляет или заменяет запись. `remove`
пропускает отсутствующий ключ. `has` проверяет наличие, `sz` возвращает число ключей.
`get(ключ)` при отсутствии ключа вызывает ошибку. `get(ключ, запас)` вычисляет запасное значение
только при необходимости. Поиск сейчас линейный.

`keys` даёт ключи как `mas` строк, `values` — значения, оба в порядке добавления записей.
`for k in m` перебирает ключи в том же порядке, так что словарь можно напечатать или
записать в файл без ручного учёта.

Имя функции с конкретными типами параметров можно присвоить переменной `all`, передать или вернуть.
В `x -> ...` параметр имеет тип `num`. Явные типы пишутся как `(num x, dec y) -> ...`.
Анонимные функции видят глобальные переменные, локальные значения передаются параметрами.

```bit
record Point:
    num x;
    num y;

fn apply(all operation, num value):
    return operation(value);

host {
    Point p = Point(2, 3);
    do(p >> x(7));
    map counts = (num);
    do(counts >> set("x", p >> x));

    all twice = x -> x * 2;
    print(apply(twice, counts >> get("x", 0)));
}
```

## Подключение файлов

`use "lib/math.bit";` подключает файл по пути относительно места, где записана директива.
Подключённые файлы делят пространство имён. Каждый путь загружается один раз, цикл вызывает
ошибку. `host { }` разрешён в главном файле.

## Сбои: recover и else

Если системная операция срывается (файла нет, каталога нет, нет связи), программа по умолчанию
завершается с кодом 1 и сообщением. Чтобы решить самой — пропустить, повторить, записать в отчёт —
оберни операции в `recover`:

```
for p in files {
    file f = p;
    recover {
        string d = f >> read;
        do(report >> append(d));
    } else {
        do(report >> append("не прочитан: {p}\n"));
    }
}
```

Если что-то внутри `recover` сорвалось, выполнение прыгает в `else`, и программа идёт дальше.
`recover` можно вкладывать — сбой ловит ближайший. Изменения, сделанные в `recover` до сбоя,
сохраняются.

Что именно сорвалось, говорит `term >> error` — текст последней пойманной ошибки (пустая строка,
если сбоев не было). Код выхода программа выбирает сама через `term >> exit(код)`:

```
recover {
    do(f >> write(data));
} else {
    print("не вышло: {term >> error}");     # не могу записать в файл: /нет/такого/x.txt
    do(term >> exit(3));
}
```

## Методы по типам

Методы вызываются через `>>`. Ниже — основные по каждому типу.

### num и dec

Арифметика и сравнения пишутся операторами. `num` — знаковое 64-битное целое, а `dec` — число
с плавающей точкой. Переполнение `num` во время выполнения можно обработать через `recover`.

| Метод | Что делает |
|---|---|
| `n >> abs` | модуль (`num` или `dec`) |
| `n >> sqrt` | квадратный корень, результат `dec` |
| `n >> pow(k)` | `n` в целой степени `k` (только `num`) |
| `a >> min(b)` / `a >> max(b)` | меньшее / большее из двух (`num` или `dec`) |
| `n >> hex` / `n >> hex(w)` | hex-текст строчными; `w` дополняет его нулями до ширины |
| `d >> fixed(k)` | текст ровно с `k` знаками после точки, с округлением |
| `n >> pad(w)` / `n >> pad_left(w)` | число текстом, дополненное до `w` символов |

Битовые операции над `num`:

| Метод | Что делает |
|---|---|
| `n >> shift_left(k)` | сдвиг битов влево на `k` |
| `n >> shift_right(k)` | сдвиг битов вправо на `k` (логический) |
| `a >> bit_and(b)` / `bit_or(b)` / `bit_xor(b)` | побитовые И / ИЛИ / исключающее ИЛИ |
| `n >> bit_not` | инвертировать все биты |

```
num m = n >> shift_left(3) >> bit_and(0xFF);
dec r = 2 >> sqrt;                 # 1.4142135623730951
num c = 3 >> pow(4);               # 81
print(255 >> hex);                 # ff
print(255 >> hex(4));              # 00ff
print(3.14159 >> fixed(2));        # 3.14
string cell = 42 >> pad_left(6);   # "    42"
```

`hex`, `fixed` и дополнение дают `string`, его можно склеивать и печатать сразу.
Деление `dec` остаётся дробным, а деление целых даёт целое: запись `dec x = 1 / 3;` —
ошибка сборки с подсказкой сделать один операнд дробным.

### string

| Метод | Что делает |
|---|---|
| `s >> sz` | длина в символах (не байтах) |
| `s >> get(i)` | символ по индексу |
| `s >> get(a:b)` | подстрока (по символам) |
| `s >> num` | прочитать десятичное целое со знаком, допустимы пробельные ASCII-символы по краям |
| `s >> lines` | `mas` строк |
| `s >> split(sep)` | `mas` кусков между разделителями |
| `s >> trim` | без пробелов, табуляций и переводов строки по краям |
| `s >> replace(что, на_что)` | каждое `что` заменено на `на_что` |
| `s >> starts(p)` / `s >> ends(p)` | `true`, если текст начинается / заканчивается на `p` |
| `s >> bytes` | `mas` байтов строки |
| `s >> run` | выполнить как команду оболочки, вернуть вывод |
| `s >> find(p)` | номер символа первого вхождения `p`, или -1 |
| `s >> contains(p)` | `true`, если `p` встречается в тексте |
| `s >> upper` / `s >> lower` | латинские буквы в другом регистре; остальные не меняются |
| `s >> code` | код первого символа; двух- и трёхбайтовый символ даёт один код |
| `s >> pad(w)` / `s >> pad_left(w)` | текст, дополненный пробелами до `w` символов |
| `s >> pad(w, ".")` | то же, с указанным символом заполнения |
| `s >> repeat(n)` | текст, повторённый `n` раз |

`n >> char` делает обратное: код символа превращается в строку из одного символа.

`pad` и `pad_left` считают ширину в символах, а не в байтах, и символ заполнения может быть
любым символом UTF-8: `"я" >> pad(3, ".")` даёт `я..`, а `"a" >> pad(3, "я")` даёт `aяя`.

Сетевые методы строки — в разделе [Сеть](#сеть).

```
string s = "Привет, мир";
print("{s >> get(0)} | {s >> get(0:5)} | длина {s >> sz}");
mas parts = "a,b,c" >> split(",");            # (a, b, c)
string t = "  текст  " >> trim;               # "текст"
bool web = url >> starts("http://");
print("привет" >> find("вет"));              # 2
print("Привет" >> get(0) >> code);           # 1055, код П
string line = 65 >> char;                    # "A"
string cell = "ab" >> pad(4, ".");           # "ab.."
string bar = "=" >> repeat(10);              # "=========="
```

Некорректный ввод или значение вне диапазона `num` вызывает ошибку, которую можно обработать
через `recover`.

### mas (массив)

| Метод | Что делает |
|---|---|
| `a >> sz` | количество элементов |
| `a >> get(i)` | элемент по индексу |
| `a >> get(i, запас)` | элемент или запасное значение, если индекса нет |
| `a >> get(a:b)` | срез (новый массив) |
| `a >> first` / `a >> last` | первый / последний элемент |
| `a >> first(d)` / `a >> last(d)` | то же, или `d`, если массив пуст |
| `a >> add(v)` | добавить элемент в конец |
| `a >> insert(i, v)` | вставить `v` перед индексом `i` |
| `a >> remove(i)` | убрать элемент с индексом `i` |
| `a >> pop` | убрать последний элемент |
| `a >> set(i, v)` | заменить элемент |
| `a >> ch(другой)` | заменить весь массив |
| `a >> keep(it ...)` | оставить подходящие (фильтр) |
| `a >> each(it ...)` | преобразовать каждый |
| `a >> find(v)` | индекс первого `v` (или -1) |
| `a >> has(v)` | есть ли `v` |
| `a >> sum` | сумма (для чисел) |
| `a >> sort` | вернуть отсортированную копию |
| `do(a >> sort)` | отсортировать исходный массив на месте |
| `a >> sort(it >> f)` | копия, отсортированная по выражению `f`; ключи `num` и `string` |
| `a >> sort(it >> f, "down")` | то же, по убыванию |
| `a >> join(sep)` | склеить строки через разделитель |
| `a >> text(от, до)` | декодировать срез байтов в строку |

`insert`, `remove`, `pop`, `add` и `set` — действия, пишутся внутри `do(...)`. Индексы у `get`,
`set`, `insert` и `remove` должны быть доказуемо в диапазоне. `first` и `last` без запаса требуют
массива, про который компилятор знает, что он не пуст; иначе — `first(d)` / `last(d)`.

`mas` — это данные, а не копия: `mas b = a` даёт второе имя тем же элементам. `>> add` и `>> set`
меняют сами данные, и это видно через любое имя; `>> ch` заменяет привязку переменной (остальные
имена продолжают смотреть на прежние данные). Поэтому массив, переданный в функцию, там можно
изменить — и это изменение увидят все, у кого он есть.

Сортировка в выражении создаёт отдельный массив. Исходник и все его общие имена сохраняют порядок
элементов. В цепочке действий внутри `do(...)` сортировка меняет полученный массив на месте.

Сортировка по выражению упорядочивает структуры и любые значения по выбранному ключу:

```bit
record User:
    string name;
    num age;

mas users = (User("b", 30), User("a", 20));
mas by_age = users >> sort(it >> age);      # сначала a, потом b
mas newest = users >> sort(it >> age, "down");
print(users >> sort(it >> age) >> each(it >> name));
```

```
mas a = (5, 3, 9, 1, 7);
print(a >> keep(it > 4));          # (5, 9, 7)
print(a >> each(it * 2));          # (10, 6, 18, 2, 14)
do(a >> insert(0, 42) >> pop);
mas words = ("кот", "пёс", "ёж");
print(words >> sort >> join(", "));
```

Если массив укоротили через другое имя, доступ проверяет текущую длину, а выход за неё можно
перехватить через `recover`. Цикл `for` учитывает исходную и текущую длину массива.

### file (файл)

| Метод | Что делает |
|---|---|
| `f >> write(текст)` | записать (перезаписать) |
| `f >> append(текст)` | дописать в конец |
| `f >> read` | весь текст |
| `f >> lines` | `mas` строк |
| `f >> get(i)` / `get(a:b)` | строка(и) по номеру |
| `f >> sz` | размер в байтах |
| `f >> exists` | существует ли |
| `f >> modified` | время последнего изменения (секунды с 1970, как `os >> now`) |
| `f >> delete` | удалить файл |
| `f >> copy(путь)` / `move(путь)` | копировать / переместить |
| `f >> save(bytes)` | записать байты как есть |
| `f >> load` | прочитать как `bytes` |
| `f >> load(смещение, размер)` | прочитать до указанного числа байтов с заданного смещения от начала |
| `f >> save(bytes, смещение)` | записать порцию по смещению от начала, при необходимости создать файл |
| `f >> name` / `path` | имя / полный путь |

При `copy` данные записываются во временный файл в папке назначения. Файл назначения
заменяется после успешной записи. `move` использует системное переименование, а между файловыми
системами копирует данные и затем удаляет исходный файл. При передаче того же пути исходный файл
остаётся на месте.

Смещение и размер неотрицательны. `load(смещение, размер)` возвращает буфер с фактическим
числом прочитанных байтов. На конце файла и за ним буфер пуст. Освобождай каждую порцию
через `do(chunk >> free)` после использования. `save(chunk, смещение)` сохраняет байты
вне записанного диапазона. Для замены всего файла используй `save(bytes)`.

```
file f = "notes.txt";
do(f >> write("первая\n") >> append("вторая\n"));
print("строк {f >> lines >> sz}, размер {f >> sz}");
do(f >> delete);
```

### dir (папка)

| Метод | Что делает |
|---|---|
| `d >> make` | создать (вместе с промежуточными папками) |
| `d >> list` | `mas` имён внутри (по алфавиту) |
| `d >> walk` | `mas` путей ко всем файлам внутри, включая вложенные папки |
| `d >> walk("info")` | `mas` записей `FileInfo`: путь, размер и время изменения |
| `d >> file(имя)` | `file` внутри папки |
| `d >> dir(имя)` | вложенная `dir` |
| `d >> exists` | существует ли |
| `d >> remove` | удалить пустую папку |
| `do(d >> remove_all)` | удалить папку вместе со всем содержимым |
| `d >> name` / `path` | имя / путь |

```
dir d = "logs";
do(d >> make);
file f = d >> file("today.txt");
do(f >> write("..."));
print(d >> list);
```

`walk` заходит во вложенные папки в глубину, каждую папку — по алфавиту. Пути начинаются с пути
самой папки. По ссылкам на папки обход не идёт, поэтому ссылка на родителя не зациклит его;
ссылки на файлы попадают в список.

```
dir src = "src";
for p in src >> walk {
    file f = p >> open;
    if os >> now - f >> modified < 3600 {
        print("менялся за последний час: {p}");
    }
}
```

`walk("info")` сохраняет тот же порядок обхода, что и `walk`. Аргумент `"info"` —
литерал: тип результата известен при сборке. Каждый элемент — встроенная структура
(она уже определена, объявлять её не нужно):

```
record FileInfo:
    string path;
    num sz;
    num modified;
```

`path` начинается с пути исходной папки, `sz` измеряется в байтах, `modified` —
в секундах с 1970 года. Это снимок: последующие изменения файла не обновляют запись.
Для обычного файла размер и время берутся из той же проверки типа на POSIX или из
перечисления каталога на Windows, без отдельного запроса за каждым полем. Ссылки на
файлы дают данные цели и могут потребовать дополнительного запроса; битые ссылки
пропускаются. По ссылкам на папки внутри дерева обход не идёт.

```
dir src = "src";
for entry in src >> walk("info") {
    print("{entry >> path}: {entry >> sz} байт, изменён {entry >> modified}");
}
```

Массивы структур поддерживают `for`, `get`, `first`, `last`, `add`, `set`, `keep`,
`each` и срезы. Пустой массив создаётся как `mas entries = (FileInfo);`.
Для печати или сортировки выбери поля: `entries >> each(it >> sz) >> sort`.
Печать и `sort` самих структур отвергаются при сборке.

`remove_all` — отдельное действие; `remove` и `delete` по-прежнему удаляют только
пустую папку. Вложенные символические ссылки и Windows junction удаляются сами,
их цели не обходятся. Если сам путь указывает на ссылку на папку, удаляется ссылка.
Обычный файл вместо корневой папки, корень файловой системы, пустой путь и конечные
компоненты `.` / `..` не принимаются. Домашняя папка защищена: на POSIX сравниваются
канонические пути к цели и `HOME`; на Windows пути разрешаются через файловые
дескрипторы и проверяются по `USERPROFILE` и `HOME` без учёта регистра. Запрещены
сам дом и любая папка, внутри которой он находится. Проверяется граница компонента:
`home` не блокирует удаление соседней `homeX`. Сбой содержит путь места остановки
удаления, в том числе вложенного файла. Его можно поймать через `recover`; уже
удалённое содержимое при этом не восстанавливается. READONLY на Windows не снимается
автоматически: при необходимости сначала вызови `read_only(false)`.

### Права доступа (file и dir)

| Форма | Что делает |
|---|---|
| `f/d >> read_only` | на macOS/Linux — нет ни одного бита записи `w`; на Windows — установлен атрибут READONLY |
| `do(f/d >> read_only(true))` | снять все три бита `w` на macOS/Linux; установить READONLY на Windows |
| `do(f/d >> read_only(false))` | установить все три бита `w` на macOS/Linux; снять READONLY на Windows |
| `f/d >> permissions` | строка прав macOS/Linux, например `"rw-r-----"` |
| `do(f/d >> permissions("rw-r-----"))` | заменить права macOS/Linux |

`f/d` в таблице означает файл или папку. `read_only(false)` добавляет право записи
владельцу, группе и остальным; прежние права не запоминаются. На POSIX остальные биты
при этом сохраняются. На Windows это файловый атрибут: он не описывает ACL и для папок
не запрещает запись в их содержимое.

`permissions` доступен только на macOS/Linux. На Windows — понятная ошибка сборки;
ACL пока не поддерживается. Строка содержит ровно девять символов: `rwxrwxrwx`, где
каждый символ можно заменить на `-` на том же месте. Неверный литерал отвергается при
сборке, неверная динамическая строка вызывает сбой для `recover`. Изменение заменяет
девять обычных битов прав и сбрасывает специальные биты setuid, setgid и sticky.
Символические ссылки при работе с правами ведут к целевому файлу; на Windows `read_only`
работает с атрибутами пути, которые возвращает системный API.

```
file f = "data.txt";
do(f >> read_only(true));
print(f >> read_only);
do(f >> read_only(false));
```

### bytes (сырая память)

`bytes` — сырой кусок памяти. Границы проверяются при сборке.

| Метод | Что делает |
|---|---|
| `mem >> take(n)` | выделить `n` байт (нулями) |
| `b >> set(i, v)` | записать байт `v` по смещению `i` |
| `b >> write(off, num)` | записать число (8 байт) по смещению |
| `b >> get(i)` | байт по смещению |
| `b >> read(off)` | число (8 байт) по смещению |
| `b >> read(off, формат, порядок)` | прочитать значение заданного формата |
| `do(b >> write(off, значение, формат, порядок))` | записать значение заданного формата |
| `b >> text` | содержимое как строка |
| `b >> sz` | размер в байтах |
| `b >> addr` | адрес данных как `num` |
| `b >> free` | освободить память (буфер и описатель) |

Формат и порядок задаются строками. `"u16"`, `"u32"` и `"i64"` возвращают `num`,
`"f32"` и `"f64"` — `dec`. Порядок — `"little"` или `"big"`.
Например, `b >> read(0, "u16", "big")` читает первые два байта. Ошибки границ и диапазона
беззнаковых значений можно обработать через `recover`.

`bytes` — сырая память, и она **не** освобождается сама. Когда память больше не нужна, освободи
её явно — как любое другое действие:

```
bytes b = mem >> take(1024);
do(b >> set(0, 42));
print("байт 0: {b >> get(0)}");
do(b >> free);                       # после free к b больше не обращайся
```

Освободи буфер один раз через любое из его имён. После этого все имена и адреса этого буфера
недействительны. За время жизни буфера отвечает программа. Компилятор освобождает временные
строки и локальные строки, для которых доказано, что они не покидают область видимости.
Строки, которые могут выйти из области видимости, могут остаться выделенными до завершения процесса.

Принят переход к обычному подсчёту ссылок: сначала для строк, затем для массивов, словарей
и записей. Интеграция в компилятор пока не завершена, поэтому описанное выше ограничение
текущей версии сохраняется. Известное ограничение выбранной модели: циклы через общие
данные сами не освобождаются — такие связи нужно разрывать явно. У `bytes` остаётся
явный `free`; атомарные счётчики не вводятся.

### mem (память компьютера)

| Метод | Что делает |
|---|---|
| `mem >> total` | всего памяти (байт) |
| `mem >> free` | свободно (значение; не путать с `b >> free`) |
| `mem >> used` | занято программой |
| `mem >> take(n)` | выделить `n` байт → `bytes` |

### random

`random >> get(от, до)` возвращает целое из включительного диапазона. При первом вызове
генератор создаёт слово из системной энтропии и использует хеш слова как зерно.
`do(random >> seed("слово"))` задаёт слово явно. Повторное зерно и те же диапазоны дают
ту же последовательность на разных архитектурах.

### os (система)

| Метод | Что делает |
|---|---|
| `os >> host` | имя компьютера |
| `os >> user` | имя пользователя |
| `os >> cpus` | число ядер |
| `os >> now` | время (секунды с 1970) |
| `os >> clock` | монотонные миллисекунды для измерения интервалов |
| `os >> procs` | список процессов: по строке `PID имя` |

`os >> procs` получает список через системные интерфейсы без запуска `ps` или
`tasklist`. Имена и доступность процессов зависят от системы и прав; формат
результата унифицирован для всех систем и отличается от прежнего вывода `tasklist`.

### term (терминал)

| Значение | Что даёт |
|---|---|
| `term >> args` | аргументы командной строки (`mas`) |
| `term >> env("ИМЯ")` | переменная окружения |
| `term >> folder` | текущая рабочая папка (`dir`, абсолютный путь) |
| `term >> pid` | pid текущего процесса |
| `term >> status` | код выхода последней команды или программы |
| `term >> error` | текст последней ошибки, пойманной `recover` |
| `term >> error_code` | числовой код последней пойманной ошибки |
| `term >> stderr` | stderr последнего `mas >> run` |
| `term >> key` | один символ с клавиатуры, не дожидаясь Enter |
| `term >> signalled` | получен ли сигнал завершения (`bool`) |

| Действие | Что делает |
|---|---|
| `term >> clear` | очистить экран |
| `term >> wait(мс)` | пауза в миллисекундах |
| `term >> exit(код)` | выйти с кодом |
| `term >> go(путь)` | сменить текущую папку; принимает `string` или `dir` |
| `term >> raw(true)` / `raw(false)` | включить или выключить немедленный режим клавиатуры |
| `term >> env("ИМЯ", "значение")` | задать переменную окружения текущей программы |

Если программа использует `term >> signalled`, при получении SIGINT или SIGTERM на macOS
и Linux значение становится `true` и остаётся таким до завершения программы. На Windows
учитываются Ctrl+C, Ctrl+Break и закрытие консоли. Флаг общий для потоков; программа сама
решает, когда завершиться. Если `signalled` не используется, действует стандартная обработка
сигналов. При закрытии консоли Windows система даёт программе ограниченное время на завершение.
Ожидание `term >> wait` и сетевое `recv` с тайм-аутом продолжают ждать после сигнала,
не увеличивая заданный тайм-аут.

`go` меняет основу для всех последующих относительных путей. Будущие `string >> run`,
`mas >> run` и `string >> start` наследуют текущую папку и окружение; уже запущенные
процессы не меняются. Изменения не затрагивают родительскую оболочку.
Сохранённое значение `term >> env("ИМЯ")` остаётся действительным после изменения окружения.
Пустое значение читается как `""`; имя должно быть непустым и не содержать `=`.
Сбой `go` или изменения `env` можно обработать через `recover`; при неудачном `go`
текущая папка остаётся прежней. На Windows обновляются и окружение процесса, и копия CRT,
чтобы чтение `env` и все способы запуска видели новое значение.

```
dir previous = term >> folder;
dir work = "рабочая папка";
do(work >> make);
do(term >> go(work));
do(term >> env("BIT_MODE", "test"));
string mode = term >> env("BIT_MODE");
do(term >> go(previous));
```

Для интерактивных программ клавиатуру можно читать посимвольно. В режиме `raw(true)` терминал
перестаёт ждать Enter и не повторяет нажатое, поэтому `term >> key` возвращается сразу после
нажатия; возвращается целый символ UTF-8, а не байт. Стрелки и другие особые клавиши приходят
своими escape-последовательностями. Если ввод не терминал (пайп или файл), `raw` ничего не делает,
а `key` просто читает следующий символ:

```
do(term >> raw(true));
string k = term >> key;
do(term >> raw(false));
print("нажато: {k}");
```

Ввод с консоли — объявлением с `input`:

```
num i >> input(0:4);           # прочитать число 0..4 (переспросит, если вне диапазона)
string s >> input;             # прочитать строку
```

Диапазон `input` — ещё и доказательство: после `num i >> input(0:4)` компилятор знает, что `i`
в 0..4, и `a >> get(i)` для массива из пяти элементов проходит проверку при сборке. Текущая длина
всё равно проверяется во время работы: массив мог укоротиться через другое имя.

### Запуск программ

Команда оболочки — `string >> run`, возвращает вывод:

```
string кто = "whoami" >> run;
```

Программа **напрямую**, без оболочки, — `mas >> run`. Первый элемент — программа, остальные —
аргументы; каждый доходит ровно как есть, пробелы и кавычки ничего не ломают:

```
mas cmd = ("convert", "моё фото.jpg", "out.png");
string out = cmd >> run;              # stdout программы
string res = cmd >> run("вход");      # то же, с текстом на stdin
num code = term >> status;            # код выхода (127 — программа не найдена)
string err = term >> stderr;          # stderr — отдельно от stdout
do(cmd >> run);                       # вывод сразу в терминал, код в term >> status
```

Рантайм читает stdout и stderr одновременно с передачей stdin. На macOS и Linux для этого
используется `poll`, на Windows выходные потоки читают два отдельных потока выполнения.

### Сеть

На Windows `fetch`, `post` и `download` работают через системный WinHTTP без запуска
внешних программ; HTTPS проверяет сертификат и имя сервера. URL со встроенными логином
или паролем пока не поддерживаются и вызывают сбой. Скачивание сначала пишет во временный
файл рядом с целью и заменяет её после полного получения. На macOS и Linux эти три метода
пока запускают `curl` без оболочки, передавая аргументы отдельно.

`ping` использует системные средства ICMP без запуска внешней программы: IPv4 и IPv6,
одно ожидание до 1 секунды после разрешения имени. На macOS и Linux нужны разрешённые
системой ICMP-сокеты; если запрос отправить нельзя или ответа нет, результат — `false`.

**HTTP:**

| Метод | Что делает |
|---|---|
| `"url" >> fetch` | GET — вернуть тело ответа |
| `"url" >> post(данные)` | POST — вернуть ответ |
| `"url" >> download("файл")` | скачать в файл |
| `"host" >> ping` | `true`, если хост отвечает |

**DNS:**

| Метод | Что делает |
|---|---|
| `"host" >> ip` | разрешить имя в IP-адрес |

**TCP и UDP (сокеты напрямую):**

| Метод | Что делает |
|---|---|
| `net >> listen(порт)` | слушать на всех IPv4-интерфейсах → `server` |
| `net >> listen(порт, "адрес")` | слушать на заданном IPv4-адресе → `server` |
| `s >> accept` | принять подключение → `conn` |
| `c >> peer` | адрес и порт собеседника, строка `ip:порт` |
| `"ip:порт" >> connect` | подключиться по TCP → `conn` |
| `"ip:порт" >> connect(мс)` | подключиться по TCP, ждать не дольше `мс` миллисекунд |
| `"ip:порт" >> udp` | открыть UDP → `conn` |
| `c >> send("...")` | отправить |
| `c >> recv` | принять строку |
| `c >> recv(размер, таймаут_мс)` | принять до указанного числа байтов как текст, с таймаутом |
| `c >> close` / `s >> close` | закрыть |

```
# сервер
server s = net >> listen(9100);
conn c = s >> accept;
string msg = c >> recv;
do(c >> send("эхо: {msg}"));
do(c >> close);
do(s >> close);

# клиент
conn c = "127.0.0.1:9100" >> connect;
do(c >> send("привет"));
print(c >> recv);
do(c >> close);
```

`listen` принимает порт 0–65535 и числовой IPv4-адрес, например `"127.0.0.1"`;
имена хостов и IPv6 здесь пока не поддерживаются. Без адреса слушаются все интерфейсы.
Для сокета включён `SO_REUSEADDR`; при ошибке сокет закрывается и возникает сбой для `recover`.
Адрес для `connect` и `udp` задаётся как числовой IPv4 и порт (`"127.0.0.1:9100"`):
порт состоит только из цифр и находится в пределах 0–65535. Неверный адрес вызывает сбой.
`peer` возвращает адрес другой стороны подключённого сокета; ошибка чтения — сбой.

`os >> clock` возвращает монотонные миллисекунды с произвольной точки отсчёта.
Вычитай два значения для измерения интервала; это не календарное время, и значения
нельзя сопоставлять после перезагрузки или между разными компьютерами.

`recv` возвращает то, что дало одно чтение из системы; по TCP длинное сообщение может прийти частями.
В `recv(размер, таймаут_мс)` размер задан в байтах (1–2147483647), таймаут — в миллисекундах
(0–2147483647). Нулевой таймаут проверяет наличие данных без ожидания. Истечение времени
можно обработать через `recover`. Штатное закрытие TCP-соединения даёт пустую строку.
Собери порции перед обработкой текста, если символ UTF-8 может оказаться между двумя чтениями.

`connect(мс)` ограничивает время ожидания подключения. На macOS и Linux используется
неблокирующий сокет с `poll`, на Windows — системный таймаут сокета. Что именно
случилось, говорит `term >> error_code`: `1` цель отказала, `2` истекло ожидание, `3` нет
маршрута до цели, `0` у ошибки нет кода. Коды одинаковы на macOS, Linux и Windows.
Обычный `connect` тоже заполняет `error_code` при отказе и недостижимости, а истёкший
`recv` даёт `2`.

### proc: чужие процессы

Найти, запустить, дождаться и остановить процесс — на macOS, Linux и Windows. На Linux и Windows
`proc` ещё читает и пишет память другого процесса, как отладчик: на Linux через `/proc/<pid>/mem`,
на Windows через системный API (`OpenProcess`, `ReadProcessMemory`, `WriteProcessMemory`,
`VirtualQueryEx`). macOS без прав отладчика закрывает память чужих процессов, поэтому там `read`,
`grab`, `scan`, `maps`, `write` и `paste` — ошибка сборки с понятным сообщением.

| Форма | Что делает |
|---|---|
| `"имя" >> proc` | найти процесс по имени (pid `-1`, если такого нет); на Windows — с `.exe` или без |
| `1234 >> proc` | процесс по pid |
| `"команда" >> start` | запустить процесс и вернуть его |
| `p >> pid` / `name` / `alive` | pid / имя / работает ли |
| `p >> wait` | дождаться завершения, вернуть код выхода |
| `p >> read(адрес)` | число (8 байт) по адресу |
| `p >> grab(адрес, n)` | `n` байт по адресу → `bytes` |
| `p >> scan(значение)` | `mas` адресов, где лежит это 8-байтное число |
| `p >> maps` | `mas` регионов памяти, каждая строка начинается с `начало-конец rwxp` |
| `do(p >> write(адрес, число))` | записать число (8 байт) |
| `do(p >> paste(адрес, bytes))` | записать байты |
| `do(p >> kill)` | остановить процесс; `wait` после этого вернёт 143 |

```
proc p = "exec ./target" >> start;
num v = p >> read(addr);
do(p >> write(addr, 0x00DEADBEEF000000));
mas hits = p >> scan(0x1122334455667788);
print("код выхода {p >> wait}");
```

Чтение или запись по адресу, которого у процесса нет, — сбой, который ловит `recover`.

Различия систем: на macOS и Linux `start` запускает команду через оболочку (`exec` превращает
оболочку в саму программу, поэтому pid и имя — программы), на Windows программа запускается
напрямую, а ведущий `exec ` отбрасывается — `"exec ./target"` работает везде. На macOS и Linux
`wait` работает для процессов, запущенных самой программой (иначе `-1`), а строки `maps` на Linux
содержат после прав ещё несколько полей. `kill` просит процесс завершиться; сразу после него
`alive` ещё может быть `true`, а `wait` дождётся конца. Отсутствующему процессу (pid `-1`) сигнал
не отправляется никогда: `kill` для него — сбой, который ловит `recover`. Примеры — [`examples/linux/`](../examples/linux/) и
[`examples/win/`](../examples/win/). В `gold_game.bit` и `gold_hack.bit` одна программа находит
другую по имени, ищет в её памяти значение и заменяет его.

## Проверки компилятора

Перед генерацией кода компилятор проверяет типы, инициализацию и диапазоны индексов.

- **Границы массивов.** Для `a >> get(i)` компилятор должен доказать диапазон индекса, например
  из `for i in 0:a>>sz-1` или проверки `if i >= 0 and i < a >> sz`. Перед доступом
  сгенерированный код проверяет текущую длину массива.
- **Переполнение `num`.** Арифметика, выходящая за 64 бита, ловится.
- **Пустые переменные.** `num e();` нельзя прочитать, пока не присвоено.
- **Типы.** Несовпадение типов — ошибка сборки.

## Сборка под разные ОС

Один исходник собирается под все поддерживаемые платформы:

```bash
./bitc build prog.bit -o prog                  # текущая ОС и архитектура
./bitc build prog.bit -o prog --arch x86_64     # x86-64 (на ARM-маке — через Rosetta)
./bitc build prog.bit -o prog --os linux        # Linux (собирать asm на Linux)
./bitc build prog.bit -o prog.exe --os windows  # Windows (нужен mingw-w64)
```

Внутри язык использует единое соглашение вызовов (System V) на всех платформах; особенности
Windows (другое соглашение, Winsock, кавычки в аргументах) спрятаны в тонких обёртках среды
выполнения.

На Windows программа ведёт себя как на macOS и Linux: текст везде в UTF-8 — в путях, командах,
аргументах и консоли (в программу встроен манифест, а консоль на время работы переключается
в UTF-8; нужна Windows 10 1903 или новее). Файлы пишутся байт в байт, `\n` остаётся `\n`.
Сообщения среды выполнения те же, что на других системах.

`./tests_win.sh хост` собирает набор тестов под Windows, запускает его на живой машине по SSH
и сравнивает вывод.

## Как устроен компилятор

- `bitc.bit` — сам компилятор на bit: лексер → парсер → проверка типов и доказательства →
  ассемблер ARM64 или x86-64.
- `rt/arm64.s`, `rt/x86_64.s` — среда выполнения в ассемблере (печать, строки, массивы, файлы,
  память, сеть, процессы). Версии для Linux и Windows выводятся из них скриптами в `tools/`;
  сгенерированные файлы лежат в репозитории, так что для сборки ничего дополнительно не нужно.
- `tools/embed_rt.bit` встраивает среду прямо в компилятор, поэтому готовый `bitc` самодостаточен.
- `bootstrap/` — ассемблер компилятора; `bootstrap.sh` собирает всё с нуля (`as` + `ld`) и
  проверяет, что компилятор, собрав сам себя, даёт тот же результат.
- `tools/build_opt.sh` собирает экспериментальный оптимизирующий вариант компилятора в `build/`.

Ни C, ни LLVM в сборке не участвуют.
