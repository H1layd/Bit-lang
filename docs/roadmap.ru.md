# План и принципы bit

[English](roadmap.md) · **Русский**

Живой документ: куда движется язык и по каким правилам. Обновляется по ходу работы.

## Принципы (главнее любой фичи)

1. **Простой контроль над системой — из коробки.** Файлы, папки, процессы, сеть, память и терминал —
   часть языка, а не библиотека, которую надо ставить. Новую возможность стоит добавлять, если она
   даёт программе больше контроля над компьютером при меньшем количестве кода.
2. **Имена угадываются с первого раза.** Никаких асемблерно-сишных сокращений; простые слова в духе
   `keep` / `each` / `has` / `sort`. Пример: битовые операции — `shift_left` / `shift_right` /
   `bit_and` / `bit_or` / `bit_xor` / `bit_not`, а не `shl` / `shr` / `band`.
3. **Свой облик, а не C / C++ / Rust.** bit опирается на собственный словарь (`do` / `ch` / `>>` /
   `host`), а не тащит чужие конвенции. Знакомый синтаксис (скобки, `;`) сам по себе не проблема,
   ломать его ради непохожести не нужно.
4. **Всё видно и последовательно.** Действия (меняют мир) — через `do` и `ch`; значения просто
   считаются. Никаких скрытых эффектов.
5. **Безопасность доказывается при сборке,** а не проверяется во время работы. Ни одна новая
   возможность не должна это ломать.

## Проход по читаемости имён

- [x] точка входа: `fn main() {}` → `host { }`
- [x] битовые операции: `shl…` → `shift_left` / `bit_and` / …
- [ ] `dec` — не очевидно, что это дробное число (кандидат на переименование)
- [ ] `mas`, `conn`, `proc` — проверить, читаются ли без догадок
- [ ] `ch` — короткое, но не всем очевидно, что это «изменить»

## Лёгкие добавки — дёшево, самосборку не трогают

- [x] **Битовые операции** методами на `>>`.
- [x] **`break` / `next`** (`next` вместо `continue` — короче и в стиле языка).
- [x] **Операции с массивами**: `insert(i, v)` / `remove(i)` / `pop`, `first` / `last` с запасом.
- [x] **Строки**: `split`, `trim`, `replace`, `starts`, `ends`.
- [x] **Математика**: `sqrt`, `pow` (целая степень), `abs`, `min` / `max`.
- [ ] **`rand`** — нужен выбор генератора и зерна (фиксированное / время / `/dev/urandom`).
- [ ] **Типизированный `bytes`**: чтение `u16` / `u32` / `float` по смещению, порядок байтов.
- [ ] **Мелочи парсера**: нет экранирования `\r`; строка с `\n` внутри `{...}` другой строки не
  разбирается (обход — через переменную).

## Контроль над системой

Цель: программа сама решает, чем закончилась системная операция, сколько данных брать и сколько ждать.

- [x] **Сбои** — `recover { } else { }`: сорвавшаяся операция уходит в `else`, программа идёт дальше;
  `term >> error` даёт текст ошибки, `term >> exit(код)` выбирает код выхода.
- [x] **Прямой запуск программ** — `mas >> run`, `mas >> run("вход")`, `term >> stderr`,
  `term >> status`, `do(cmd >> run)`. Аргументы доходят ровно как есть на всех ОС; на macOS и Linux
  stdout и stderr не блокируют друг друга.
- [x] **`file >> move`**.
- [ ] **Потоковый доступ**: читать файл порциями и по смещению; `recv` с размером порции и таймаутом,
  сборка сообщения из нескольких чтений.
- [ ] **`a >> sort` меняет массив внутри выражения** — решить: менять только через
  `do(a >> sort)` или в выражении возвращать копию.
- [ ] Снова запустить Linux-рантайм на настоящей машине после последних изменений (macOS и
  Windows 11 проверены).

## По-крупному — порядок важен

Трогает парсер, типы, генерацию кода и память; должно пережить самосборку.

1. **Структуры (записи)** — главный разрыв: сейчас всё моделируется параллельными массивами.
2. **map (словарь)** — после структур почти бесплатно.
3. **Правила памяти и общих данных** — текущая модель описана в справочнике (строки освобождаются
   сами, `bytes` — явно через `free`, `mas` при присваивании общий). Структуры и словари должны
   следовать тем же правилам.
4. **Функции-значения** — `x -> x * 2`; стрелка `->` зарезервирована под это.
5. **Модули** — ради самого компилятора (17k+ строк в одном файле).
6. **Оптимизатор** — экспериментальная оптимизирующая сборка уже есть (`tools/build_opt.sh`).

## Не сейчас — честно

- **FFI (вызов C)** — против идеи, что вся цепочка своя. Это был бы другой язык.
- **Потоки / async** — одно соединение за раз пока достаточно.
- **Юникод-локали, отладочная информация DWARF, пакетный менеджер, BSD / wasm, беззнаковые числа,
  даты и часовые пояса, `const`, кортежи** — рост вширь и удобство; вернёмся при конкретной нужде
  или живых пользователях.
