# План и принципы bit

[English](roadmap.md) · **Русский**

Живой документ: куда движется язык и по каким правилам. Обновляется по ходу работы.

## Принципы (главнее любой фичи)

1. **Простой контроль над системой — из коробки.** Файлы, папки, процессы, сеть, память и терминал —
   часть языка, а не библиотека, которую надо ставить. Новую возможность стоит добавлять, если она
   даёт программе больше контроля над компьютером при меньшем количестве кода.
2. **Имена угадываются с первого раза.** Никаких асемблерно-сишных сокращений; простые слова в духе
   `keep` / `each` / `has` / `sort`. Пример: битовые операции — `shift_left` / `shift_right` /
   `bit_and` / `bit_or` / `bit_xor` / `bit_not`, а не `shl` / `shr` / `band`.
3. **Свой облик.** У bit есть узнаваемые конструкции, включая цепочки `>>` и точку входа `host`.
   Сохранять или менять каждую форму стоит по тому, насколько легко понять код.
4. **Эффекты видны в коде.** Должно быть понятно, какие операции меняют состояние.
   Присваивание сохраняет форму `do(x >> ch(значение));`.
5. **Что можно доказать — доказывается при сборке:** типы, пустые переменные, диапазоны индексов.
   Длина массива дополнительно проверяется во время работы: массив может измениться через другое имя.
   Ни одна новая возможность не должна это ослаблять.

## Сначала упростить язык целиком

Первый этап развития — пересмотреть базовые правила bit. Результат должен быть проще выучить по
небольшому набору общих правил. Структуры, словари, функции-значения и модули уже есть;
согласованные правила распространятся и на них.

- [ ] **Названия команд.** Найти сокращения и слова, смысл которых приходится угадывать.
  Начать с методов и согласовать каждое новое имя с примерами вызова.
- [ ] **Объявления.** Сравнить явные и выводимые типы, пустые объявления и формы создания массивов.
- [x] **Блоки.** `host { ... }` сохраняется. Функции, условия, циклы и обработчики сбоев
  поддерживают двоеточие и отступы.
- [ ] **Выражения и действия.** Выработать одно правило для `do`, `>>` и вызовов функций.
  Сейчас некоторые цепочки могут менять данные внутри выражения.
- [ ] **Операции над данными.** Свести к общим правилам доступ по индексу, срезы, запасные
  значения, преобразования типов и поведение общих данных при присваивании.
- [ ] **Системные операции и сбои.** Сравнить работу с файлами, сокетами и процессами. Проверить,
  где различия в способах передать данные, получить результат и обработать ошибку можно убрать.
- [ ] **Проверка результата.** Сравнить «до» и «после» на обычном счётчике, обработке массива,
  копировании файла и запуске процесса. Считать обязательные конструкции и правила, которые
  приходится помнить. По итогам согласовать, что объединить, сделать необязательным или убрать.
  Для согласованных несовместимых изменений описать переход и обновить самосборку, примеры и тесты.

### Читаемость имён

- [x] точка входа: `fn main() {}` → `host { }`
- [x] битовые операции: `shl…` → `shift_left` / `bit_and` / …
- [ ] `dec` — не очевидно, что это дробное число (кандидат на переименование)
- [ ] `mas`, `conn`, `proc` — проверить, читаются ли без догадок
- [x] `ch` сохраняется в форме присваивания `do(x >> ch(значение));`

## Лёгкие добавки — дёшево, самосборку не трогают

- [x] **Битовые операции** методами на `>>`.
- [x] **`break` / `next`** (`next` вместо `continue` — короче и в стиле языка).
- [x] **Операции с массивами**: `insert(i, v)` / `remove(i)` / `pop`, `first` / `last` с запасом.
- [x] **Строки**: `split`, `trim`, `replace`, `starts`, `ends`.
- [x] **Математика**: `sqrt`, `pow` (целая степень), `abs`, `min` / `max`.
- [x] **`random`**: включительные целочисленные диапазоны. Зерно — хеш слова из энтропии ОС или из `seed(слово)`.
- [x] **Типизированный `bytes`**: чтение и запись `u16`, `u32`, `i64`, `f32` и `f64` с заданным порядком байтов.
- [x] **Экранирование строк**: `\r` и экранированные пробельные символы внутри интерполяции.
- [x] **Текст и числа для настоящих программ**: `find`, `contains`, `upper`, `lower`, `code`,
  `char`, `pad`, `pad_left`, `repeat`; `hex` с шириной и `fixed` для дробей; дополнение
  работает и для чисел. Деление целых в `dec` — ошибка сборки с подсказкой.
- [x] **Сортировка по полю**: `a >> sort(it >> f)` и `sort(it >> f, "down")` упорядочивают
  структуры и любые значения по ключу `num` или `string`.
- [x] **Обход словаря**: `m >> keys`, `m >> values` и `for k in m` в порядке добавления.
- [x] **Нет предела параметров**: аргументы сверх регистров идут через стек, поэтому
  параметров у функции может быть сколько нужно.
- [x] **`pick`**: выбор по значению без провалов — `pick x { 1 { } 2, 4 { } else { } }`.
- [x] **Потоки**: `thread имя { ... }` запускает второй ход на своём стеке, а
  `do(имя >> wait)` дожидается его. Потоки видят глобальные переменные.
- [x] **Замки**: `lock guard;`, `do(guard >> enter)` и `do(guard >> leave)` защищают общие данные.
- [x] **Немедленная клавиатура**: `do(term >> raw(true))` перестаёт ждать Enter и повторять нажатое,
  а `term >> key` возвращает один символ UTF-8, так что интерактивные программы возможны.
## Контроль над системой

Цель: программа сама решает, чем закончилась системная операция, сколько данных брать и сколько ждать.

- [x] **Сбои** — `recover { } else { }`: сорвавшаяся операция уходит в `else`, программа идёт дальше;
  `term >> error` даёт текст ошибки, `term >> exit(код)` выбирает код выхода.
- [x] **Прямой запуск программ** — `mas >> run`, `mas >> run("вход")`, `term >> stderr`,
  `term >> status`, `do(cmd >> run)`. stdout и stderr читаются параллельно. Обновлённый Windows-рантайм ещё нужно проверить под нагрузкой.
- [x] **`file >> move`**.
- [x] **Копирование файлов** через временный файл в папке назначения и проверка операций с одним путём.
- [x] **Проверка текущих границ**, строгий разбор `string >> num` и корректный выход из `recover`.
- [ ] Освобождение строк, которые могут выйти из своей области видимости.
- [x] **Потоковый доступ**: чтение файла порциями, запись по смещению, текстовый `recv` с размером
  порции и таймаутом.
- [ ] Проверить потоковый доступ запуском под Linux и Windows.
- [x] **Сортировка**: `a >> sort` возвращает копию, `do(a >> sort)` сортирует на месте.
- [x] **`d >> walk`** — все файлы внутри папки, включая вложенные, без захода по ссылкам на папки;
  **`f >> modified`** — время последнего изменения.
- [x] **`connect(мс)`** — TCP-подключение с ограниченным ожиданием: на macOS/Linux
  неблокирующий сокет с `poll` и `SO_ERROR`, на Windows системный таймаут сокета.
  **`term >> error_code`** — стабильный числовой код последней пойманной ошибки
  (1 отказ, 2 истекло ожидание, 3 нет маршрута, 0 без кода) на macOS, Linux и Windows;
  обычный `connect` и истёкший `recv` тоже его заполняют.
- [x] **`proc` на Windows** через системный API (`OpenProcess`, `ReadProcessMemory`,
  `WriteProcessMemory`, `VirtualQueryEx`), проверено на Windows 11. Та же программа работает на Linux.
- [x] **Прогон на живой Windows**: `tests_win.sh` проверяет 39 тестов выполнения и 53 ожидаемые
  ошибки компиляции на Windows 11. Файловые тесты используют сам bit; для команд, процессов
  и большого объёма stdin/stderr есть Windows-варианты. Пропускается только проверка запрета
  записи в корень: она зависит от ОС и прав. Неожиданная ошибка сборки теперь проваливает
  прогон. Исправлен разбор кодов выхода Windows как статусов POSIX. Ранее исправлены: запись файлов в текстовом режиме
  (`\n` превращался в `\r\n`), кириллица в путях, командах и аргументах ломалась из-за ANSI-кодировки,
  сообщения среды выполнения были транслитом. Программы на Windows теперь целиком в UTF-8.
- [ ] Прогнать обновлённые рантаймы на живом Linux.
- [x] Linux в Colima: Debian, x86-64 под QEMU, непривилегированный пользователь;
  95/95 и самосборка сошлись. Проверена защита HOME и её предков при `remove_all`.
- [x] Защита HOME/USERPROFILE и их предков проверена на живой Windows; исправление
  закоммичено (`95be464`). Прежний Linux-сервер удалён; в QEMU отмечены редкие сбои
  самого эмулятора, нативный Linux остаётся отдельной проверкой.
  Проверка после исправления потоков: два полных прогона под QEMU дали 125/126 и
  124/126; в разных тестах аварийно завершался процесс QEMU. В серии из 500 запусков
  одного примера QEMU упал 1 раз на старой версии и 4 раза на новой; дампы обоих
  процессов — ARM64 QEMU. После выравнивания стека в новой парной серии по 500
  запусков QEMU упал 8 раз до и 7 раз после; дампы также принадлежат процессу QEMU.
  Финальный полный прогон после исправления выравнивания: 128/128 и самосборка.
  Надёжность на нативном Linux этими замерами не установлена.

### Сервисные возможности и сигналы

- [x] **`ping` без внешней программы**: системный ICMP, IPv4 и IPv6; проверка
  с подставным исполняемым файлом и отдельные тесты на macOS, Windows и Linux под QEMU.
  HTTP/HTTPS на macOS и Linux через `curl` ещё предстоит заменить.
- [ ] **HTTP/HTTPS без `curl`**: на Windows `fetch`, `post` и `download` используют
  WinHTTP, проверяют TLS и сохраняют целевой файл при обрыве. URL со встроенными
  учётными данными пока не поддержаны. Локальные проверки: `python3 tools/test_http_windows.py --stack-check хост`
  (нужны Python 3 на Windows и OpenSSL для одноразового тестового сертификата). Реализации для macOS и Linux ещё не готовы.
- [ ] **Двоичные данные в сокетах**: `send(bytes)` и `recv_bytes(размер, таймаут)`
  реализованы; TCP/UDP, нулевые байты, таймаут и закрытие проверены на macOS и Linux.
  Windows-версия собирается, но ещё требует запуска и проверки на Windows.
  Сохранение `SOCKET` без обрезания до 32 бит и обработка сбоев проверены на подставных
  значениях в `tools/test_windows_socket_handles.py`; реальная проверка Windows остаётся.

- [x] `net >> listen(порт, "адрес")`, `c >> peer`, `SO_REUSEADDR` и `os >> clock`.
  Проверены обе архитектуры macOS (217/217), Windows (54/54 и 53 ошибки сборки)
  и Linux под QEMU (109/109 и отдельно новая проверка строки ошибки). На Linux исправлен
  `SO_ERROR` в `connect(мс)`; на macOS — `O_NONBLOCK`, передача аргумента `fcntl` и
  номер строки ошибки. Разбор адреса и порта ограничен, длинный ввод не повреждает стек.
  Сквозной тест таймаута на гарантированно молчащем узле остаётся открытым.
- [x] **Выравнивание стека x86-64**: статический обход всех 207 функций macOS,
  215 Linux и 269 Windows выявил 24 места в Windows и 11 в macOS/Linux; после
  исправления замечаний нет. На Windows
  68 тестовых программ прошли с ловушкой перед каждым вызовом; на macOS и Linux
  проверены 11 выбранных программ.
  `python3 tools/test_x86_stack_audit.py` входит в общий прогон; на Windows доступен
  `./tests_win.sh --stack-check хост`. Проверка анализирует выравнивание RSP, но не
  доказывает размер shadow space, сохранение регистров или корректность чужих библиотек.
- [x] Сигналы `term >> signalled`: отдельные дочерние программы проверяют SIGINT и
  SIGTERM на обеих архитектурах macOS и Linux под QEMU; Ctrl+C, Ctrl+Break и закрытие
  консоли проверены на живой Windows. Проверены обычное поведение без подписки,
  флаг в потоке и сохранение ожидания и сетевого тайм-аута при сигналах.
  Нативный Linux остаётся отдельной проверкой.

## Этапы системных возможностей

Состояние уже начатых этапов. Завершение каждого изменения включает проверки и обновление документации.

1. **Тесты на настоящих машинах.** Для Windows готово (`tests_win.sh`), включая варианты тестов,
   которым нужны POSIX-утилиты на macOS/Linux. Дальше — прогон на Linux, когда VPS снова доступен.
2. ~~**Процессы на macOS.**~~ Готово: `start`, `pid`, `name`, `alive`, `wait`, `kill` и `"имя" >> proc`
   работают на macOS (libproc, для системных процессов — `sysctl`); доступ к памяти там — понятная
   ошибка сборки. Попутно: `kill` для ненайденного процесса (pid `-1`) на Linux отправил бы сигнал
   всем процессам пользователя — теперь это сбой.
3. ~~**Рабочая папка и окружение.**~~ Готово: `term >> folder`, `do(term >> go(путь))`
   (`string` или `dir`), `do(term >> env("K", "V"))`. Новые `run` и `start` наследуют папку
   и окружение. На Windows обновляются и окружение процесса, и копия CRT. Проверены сохранённые
   значения `env`, кириллица, пробелы, неверные имена переменных и неудачный переход в папку.
4. ~~**Файловая система до конца.**~~ Готово: `read_only` на трёх ОС; `permissions`
   на macOS/Linux со строгими строками из девяти символов и проверкой литералов при сборке.
   `do(d >> remove_all)` удаляет дерево, не обходит цели ссылок и junction.
   `d >> walk("info")` возвращает массив `FileInfo` (`path`, `sz`, `modified`);
   обычные файлы не требуют отдельного запроса за размером и временем. Добавлены массивы
   структур. Самосборка сошлась, macOS: 187/187; Windows: 39 запусков и 53 ошибки сборки.

## Дальше — план: устойчивый язык и большой проект

**Контрольная остановка по указанию автора:** продолжать работу до пакетного менеджера.
Перед реализацией пакетного менеджера остановиться, отчитаться и ждать команды автора.
Пакетный менеджер и следующие этапы до этой команды не начинать.

**Что делаем сейчас:** убираем неявные внешние утилиты из компилятора и рантайма;
HTTP на macOS/Linux и собственная сборка без `as`/`ld` ещё не готовы. Отдельно
двоичные сокеты реализованы, но ещё требуют проверки на Windows. Этап памяти остаётся незавершённым:
сначала строки, затем `mas`, `map` и записи. Пункты ниже — направления, а не
обещание выполнять только в порядке номеров; остановка перед пакетным менеджером
сохраняется. Лицензию и новые решения языка выбирает автор.

1. ~~**Закрыть текущий блок.**~~ Защита HOME/USERPROFILE и их предков проверена на Windows,
   macOS и Linux под QEMU и закоммичена. Нативный Linux остаётся отдельной проверкой.
2. **Открыть проект людям.** Файл `LICENSE` (лицензию выбирает автор; без неё код по закону
   нельзя использовать). GitHub Actions: сборка, самосборка и тесты на macOS, Linux и Windows
   при каждом коммите, значок в README. Прогон на живом Linux. Сообщения компилятора и среды
   выполнения на английском по умолчанию, русский — опцией, как в документации.
3. **Память и долгие программы.** Определить владение строками, массивами, словарями
   и структурами, возврат значений из функций и общие данные при присваивании. Освобождать
   объекты без утечек и преждевременного освобождения; явное управление `bytes` сохраняется.
   Принято автором: обычный, неатомарный подсчёт ссылок. Порядок — сначала `string`, затем
   `mas`, `map` и записи. После каждого этапа сравнить время самосборки и пик `mem >> used`;
   заметное замедление показать автору до перехода дальше. Циклы через общие данные
   автоматически не освобождаются. Состояние реализации — в [плане памяти](memory.ru.md).
4. **Согласованные правила языка.** Пройти этап упрощения выше: объявления, имена,
   граница между значением и действием, `do`, `>>`, копирование и изменение общих данных.
   Снять оставшиеся ограничения обычных программ, включая взаимную рекурсию.
   Передача более шести параметров уже реализована и проверена.
   Решения по синтаксису и новым именам принимает автор.
5. **Возможности для любых программ.** Потоки, замки и сырой ввод терминала уже есть;
   остаются перечисления и «значение или ничего» (enum/optional), двоичный обмен по
   сокетам и общение с запущенным процессом по ходу работы (писать в stdin, читать stdout).
   Нужны HTTP и TLS без внешнего `curl` на macOS/Linux и беззнаковые числа, если
   понадобятся формату данных. Каждое новое имя и синтаксис — согласовать с автором.
6. **Библиотеки и удобная установка пакетов.** Развить `use` в систему модулей
   с пространствами имён и явным публичным интерфейсом. Добавить описание проекта
   и зависимостей, версии библиотек, lock-файл, локальный кеш и загрузку одной командой.
   Подробности и критерий готовности — ниже.
7. **Устойчивый выпуск.** Автоматические проверки macOS, Linux и Windows, самосборка,
   длительные прогоны с контролем памяти, понятные диагностические сообщения.
   Готовые сборки компилятора, простая установка, версии и правила совместимости;
   команды проверки и форматирования проектов.
   Учебник «bit за час», галерея примеров, по возможности онлайн-песочница.
   Отладочная информация (DWARF), чтобы отладчик показывал строки bit.
8. **Собственная IDE для bit.** Редактор проектов со сборкой, запуском, диагностикой,
   навигацией и дополнением кода; затем отладка. Ядро инструментов писать на bit,
   развивая язык на реальной программе. Подробности и критерий готовности — ниже.
9. **Признание на GitHub.** Распознавание языков на GitHub делает библиотека Linguist; язык
   добавляют pull request'ом и только когда он уже широко используется. Условия из руководства
   для участников Linguist: не меньше 2000 файлов на расширение, проиндексированных поиском
   GitHub за последний год, без форков и с разбросом по разным репозиториям — причём репозитории
   самого автора языка из подсчёта вычитаются (`-user:`). Linguist прямо пишет, что заявки
   по совсем новым и любительским языкам закрывают. Нужны ещё грамматика TextMate под одной
   из одобренных свободных лицензий, добавленная через `script/add-grammar` как сабмодуль,
   не меньше двух примеров с указанной лицензией и ссылка на результаты поиска GitHub в PR.
   Расширение `.bit` в `languages.yml` пока свободно, так что отличать его от другого формата
   не требуется. Путь: реальные пользователи и проекты → грамматика для редакторов → PR
   в Linguist, именно в таком порядке; счётчик растёт из чужого кода, а не из репозиториев автора.
10. **BitOS — рабочее название большого проекта.** Создать собственную системную среду
    на bit и развить её в экспериментальную ОС с ядром, процессами и файловой системой.
    Проверять язык на исходниках этого проекта, выделять повторяемые части в библиотеки
    и устанавливать их через пакетный менеджер.

### Библиотеки и пакеты

Принято автором в передаче по пакетам: единая команда `bit`, `bitc` остаётся синонимом;
реестр называется **nibble**. Сначала это GitHub-репозиторий-индекс без своего сервера;
публикация — через pull request в индекс. Ожидаемый сценарий — `bit add json`, после
которого зависимость доступна проекту без ручной настройки. Этот раздел уточняет план,
но не отменяет контрольную остановку перед реализацией пакетного менеджера.

- [ ] Сначала согласовать пространства имён, публичные и внутренние объявления,
  библиотеку без `host` и обращение к её функциям. Сейчас `use` объединяет имена файлов.
  Предложить автору варианты с примерами, затем реализовать модули и тесты.
- [ ] Согласовать импорт пакета (предложение: `use json;` рядом с `use "путь.bit";`),
  точку входа библиотеки (предложение: `lib.bit`), имена и форматы файлов проекта.
- [ ] Предложения для согласования: `bit.deps` со строками «имя версия» (`1.2` означает
  последнюю `1.2.x`), `bit.lock` с точной версией, HTTPS-источником и полным SHA коммита;
  индекс `index/<имя>` со строками «версия git-адрес полный SHA». Более сложные диапазоны
  версий отложить. Разрешение транзитивных зависимостей и диагностику конфликтов
  определить до реализации формата.
- [ ] После контрольной остановки и команды автора: пакетный модуль на самом bit,
  подключённый к компилятору; единая команда `bit` и совместимость с `bitc`.
  Предложенные подкоманды: `add`, `remove`, `update`, `search`, `publish`; недостающие
  зависимости из lock-файла автоматически загружаются при `build` / `run`.
- [ ] Локальный тестовый индекс без сети: добавление, lock-файл, повторная сборка из кеша,
  неверный хеш и плохое имя. Загрузка и проверка пакетов должны работать без системного
  `git` и других утилит. Способ получения и проверки содержимого, включая связь с SHA
  коммита или отдельный хеш архива, определить до реализации и проверить на трёх системах.
- [ ] Только HTTPS; при установке не выполнять скрипты. Имя пакета: 1–64 символа
  из `a-z`, `0-9`, `-`, без путей. Проверять полный SHA скачанного коммита и сообщать
  ревизию индекса. Несовпадение — понятная ошибка без продолжения сборки.
- [ ] Неизменяемый кеш `~/.bit/nibble/<имя>/<версия>-<коммит>/`
  (Windows: `%USERPROFILE%\.bit\nibble\...`); сборка без сети при наличии всех
  проверенных зависимостей из lock-файла. Согласовать размещение кеша до реализации.
- [ ] `update`, `remove`, `search`; `publish` проверяет сборку, точку входа и тег версии,
  затем готовит запись индекса и текст PR. PR отправляет автор пакета.
- [ ] Подготовить структуру индекса, правила публикации и пакет-пример; репозиторий
  на GitHub создаёт автор. Обновить справочник, README и план на двух языках.
- [ ] Первые стандартные пакеты nibble: `json`, дата и время (форматирование, разбор,
  часовые пояса), шаблоны поиска или регулярные выражения, хеши и кодировки (sha256, base64,
  hex), криптографически стойкие случайные байты.
- [ ] Стандартные библиотеки на bit: данные, конфигурации, форматы файлов, алгоритмы.
  Свой сервер реестра, зеркало, поиск и сайт на bit — отдельный последующий этап.
- [ ] Критерий готовности: новый проект устанавливает библиотеку одной командой,
  импортирует её публичный интерфейс и собирается на другой машине по тому же lock-файлу;
  повторная сборка из кеша работает без сети. Недостающие возможности языка фиксировать
  и согласовывать с автором, не обходить внешними реализациями.

### Собственная IDE для bit

Отдельный продукт перед этапом ОС. Название, интерфейс и способ реализации графики
согласовать с автором перед разработкой; расширение существующего редактора может быть
промежуточной проверкой инструментов, но не заменяет собственную IDE. Ядро инструментов
писать на bit; недостающие средства интерфейса и системные возможности добавить в план
языка без FFI.

1. **Подготовить компилятор.** Машиночитаемая диагностика с файлами и позициями,
   информация о символах и типах, устойчивый разбор незавершённого кода. Общие части
   компилятора выделить в модули для повторного использования редактором.
2. **Редактор и проекты.** Открытие папки, дерево файлов, вкладки, редактирование,
   поиск и замена, сохранение, восстановление несохранённого текста и настройки проекта.
   Проверить русский текст, Unicode, клавиатурную навигацию и большие исходники.
3. **Повседневная разработка.** Сборка и запуск через `bit`, панель вывода, остановка
   программы, ошибки с переходом к строке, форматирование, просмотр зависимостей nibble.
4. **Понимание кода.** Переход к определению, поиск использований, информация о типах,
   дополнение кода и переименование символа с учётом областей видимости. Обновлять
   сведения при редактировании без полной самосборки компилятора на каждое нажатие.
5. **Отладка.** Сначала добавить отладочную информацию и нужную поддержку компилятора;
   затем точки останова, шаги, стек вызовов и просмотр значений. Системные средства
   и протокол отладчика выбрать отдельно; не объявлять отладку готовой по одному запуску.
6. **Критерий готовности.** На macOS, Windows и Linux открыть исходники компилятора,
   изменить их, собрать и запустить результат, перейти по диагностике и отладить
   небольшую программу. Саму IDE собирать воспроизводимо из её исходников.

### BitOS: от системной среды к собственной ОС

Рабочее название проекта можно поменять. Это долгосрочная цель с отдельными
проверяемыми рубежами; первый устойчивый выпуск bit не требует законченной ОС.

1. **Системная среда на Linux.** Собственная оболочка на bit, запуск и надзор за службами,
   журнал событий, управление файлами, сетью и пакетами. Среду можно запустить в виртуальной
   машине и пользоваться ею как единым продуктом.
2. **Подготовка к собственному ядру.** Отдельная цель сборки без libc и ОС хоста
   (freestanding), загрузочный вход, размещение кода и памяти, минимальный рантайм,
   доступ к аппаратуре и обработка прерываний. Текущий рантайм зависит от системных API;
   этот рубеж требует работы над компилятором и платформенным слоем.
3. **Первый запуск собственного ядра в QEMU, x86-64.** Загрузка, вывод в последовательный
   порт, выделение памяти и таймер. Первый результат — воспроизводимо собираемый образ,
   который загружается и выполняет код ядра на bit.
4. **Минимальная самостоятельная ОС.** Виртуальная память и изоляция процессов,
   планировщик, системные вызовы, базовые драйверы, файловая система и пользовательская
   оболочка. Установка и запуск программ на bit внутри BitOS.
5. **Самосборка внутри BitOS.** Перенести компилятор и инструменты в собственную систему:
   получить исходники и пакеты, собрать программу и сам компилятор изнутри ОС.

Каждый рубеж должен давать запускаемый результат и список конкретных ограничений языка,
обнаруженных при разработке. Новые языковые механизмы и их имена согласуются с автором.


## Возможности языка

- [x] **Структуры** с типизированными полями и общими данными при присваивании.
- [x] **Словари** со строковыми ключами, одним типом значения и линейным поиском.
- [x] **Функции как значения** с конкретными типами параметров и синтаксисом стрелок.
- [x] **Программы из нескольких файлов** с относительными путями в `use` и общим пространством имён.
- [x] **Оптимизирующая сборка**: `%` на положительную степень двойки использует битовые операции.

## Не сейчас — честно

- **ACL Windows** — отдельная модель прав; пока доступен атрибут `read_only`.
- **FFI (вызов C)** — против идеи, что вся цепочка своя. Это был бы другой язык.
- **Юникод-локали, BSD / wasm, `const`, кортежи** — рост вширь и удобство; вернёмся
  при конкретной нужде или живых пользователях. Потоки, беззнаковые числа, даты и время
  перенесены в план выше.
