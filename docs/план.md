# План и принципы языка bit

Живой документ: куда двигаемся и по каким правилам. Обновляется по ходу.

## Принципы (главнее фич)

1. **Имена угадываются с первого раза.** Никаких асемблерно-сишных сокращений.
   Полные понятные слова в духе уже существующих `keep` / `each` / `has` / `sort`.
   Пример исправления: битовые операции названы `shift_left` / `shift_right` /
   `bit_and` / `bit_or` / `bit_xor` / `bit_not`, а не `shl` / `shr` / `band` / …
   Нельзя заставлять читателя гадать, что значит имя.
2. **Свой облик, а не C / C++ / Rust.** Опираемся на уже сложившийся собственный
   словарь (`do` / `ch` / `>>` / `keep`), а не тащим чужие конвенции. Отличие и
   читаемость — часть смысла проекта. При этом знакомый синтаксис (скобки, `;`)
   сам по себе не проблема — ломать его ради «непохожести» не нужно.
3. **Всё видно и последовательно.** Действия (меняют мир) — через `do` и `ch`;
   значения — просто считаются. Никаких скрытых эффектов.
4. **Безопасность доказывается при сборке**, а не проверяется в рантайме.
   Любая новая фича не должна ломать это свойство.

## По-крупному — настоящая работа, порядок важен

Трогает парсер + типы + кодген + память, должно пережить самосборку.

1. **Дисциплина алиасинга** — дорешать подсчёт ссылок (Stage A: заголовок-счётчик
   и `bytes` уже в рантайме; осталась эмиссия inc/drop в компиляторе). Это фундамент
   под структуры и map.
2. **Ошибки** — ✅ первый шаг: `recover { … } else { … }`. Сбой внутри (нет файла,
   нет каталога, любой `_bit_die`) уходит в `else`, программа живёт дальше; вне
   `recover` — как раньше, выход с кодом 1. Свои `setjmp`/`longjmp` (без libc,
   одинаково на всех ОС). Дальше: текст ошибки в `else` (`term >> error`), выбор кода выхода.
3. **Структуры (записи)** — главный разрыв: сейчас всё моделируется параллельными
   массивами.
4. **map (словарь)** — после структур почти бесплатно.
5. **Функции-значения** — указатели на функции (`x -> x * 2`); стрелка `->`
   зарезервирована под это.
6. **Модули** — ради поддерживаемости самого компилятора (17k+ строк в одном файле).

## Из аудита GPT (тестировщик)

Цель: программа сама управляет исходом системных операций, размером данных и ожиданием.

- [x] `file >> move` был в подсказке, но не работал — сделан (copy + remove).
- [x] Сбой операции больше не обязан убивать программу — `recover / else`.
      Проверено на macOS (arm64, x86-64) и Windows 11; Linux — не запускался.
- [x] **Текст ошибки в `else`** — `term >> error`; код выхода — `term >> exit(код)`.
      Проверено на macOS (arm64, x86-64) и Windows 11.
- [x] **Прямой запуск программ** — `mas >> run` / `mas >> run("вход")`, `term >> stderr`,
      `term >> status`; `do(cmd >> run)` — вывод сразу в терминал. Unix: fork + poll
      (stdout и stderr одновременно, без взаимной блокировки). Windows: свои кавычки
      аргументов по правилам MSVC (CRT `_spawnvp` их не ставит — это заодно починило
      `post` с пробелами), каналы с `_O_NOINHERIT`. Проверено: macOS обе арки, Windows 11.
      На Windows stdout и stderr читаются по очереди: каналы по 1 МБ, при большем stderr
      возможна остановка.
- [ ] **Мелочи парсера**: нет экранирования `\r`; строка с `\n` внутри `{...}` другой строки
      не разбирается (обход — через переменную).
- [ ] **Потоковый доступ**: чтение файла порциями и по смещению; `recv` с размером
      порции и таймаутом, сборка сообщения из нескольких чтений.
- [ ] **`a >> sort` мутирует массив внутри выражения** — решить: мутация только через
      `do(a >> sort)` или в выражении возвращается копия.

## Забиваем — честно, пока не нужно

- **FFI (вызов C)** — против идеи «вся цепочка своя, без C / LLVM». Это был бы
  другой язык.
- **Потоки / async** — одно соединение за раз пока достаточно.
- **Юникод-локали, DWARF-отладка, пакетный менеджер, оптимизатор, BSD / wasm,
  беззнаковые числа, даты-таймзоны, `const`, кортежи** — рост вширь и качество жизни;
  вернёмся при конкретной боли или живых пользователях.
