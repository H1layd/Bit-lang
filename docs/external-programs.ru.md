# Внешние программы: проверка bit

Состояние на 27 ноября 2026 года. Цель: пользовательская программа и сам
компилятор не запускают сторонние утилиты неявно. Пользователь по-прежнему
может явно запустить нужную команду через `run` или `start`. Системные API и
библиотеки ОС — отдельная зависимость, не запуск утилиты.

| Где | Что запускается сейчас | Что нужно сделать |
|---|---|---|
| `fetch`, `post`, `download` | На Linux запускается `curl`; macOS использует системную библиотеку libcurl, Windows — WinHTTP | Убрать запуск программы на Linux; собственный HTTP-транспорт остаётся отдельной задачей. |
| `os >> procs` | Утилиты больше не запускаются: системные интерфейсы macOS, Linux и Windows | Поддерживать проверку без `ps` и `tasklist`; формат — строки `PID имя`. |
| `os >> cpus` | Утилиты больше не запускаются: `sysconf` на macOS/Linux, `GetSystemInfo` на Windows | Поддерживать проверку без `getconf`. |
| `bitc asm` | Система и архитектура встроены при сборке компилятора, рабочая папка получается через системный API | Поддерживать проверку без внешних команд. |
| `bitc build` и `bitc run` | `as` и `ld` запускаются напрямую; Windows-кросс-сборка вызывает `x86_64-w64-mingw32-gcc`. Компилятор сам находит macOS SDK и не запускает `uname`, `pwd`, `mktemp`, `rm` или `xcrun`. | Заменить ассемблер и линковщик собственным генератором объектных и исполняемых файлов. |
| `bootstrap.sh` | Оболочка, `uname`, `mkdir`, `as`, `ld`, на macOS `xcrun`, затем компилятор и `cmp` | Разработать автономный путь первоначальной установки; до этого скрипт требует инструменты разработки. |

`bitc run` по смыслу запускает **саму собранную программу**, выбранную
пользователем, напрямую, без оболочки: это назначение команды, а не скрытый
запуск утилиты. Аналогично
`string >> run`, `mas >> run` и `start` запускают программу по явной команде
bit-кода. При строковом запуске используется оболочка; массив аргументов
запускает программу напрямую. Генераторы рантайма, Python-тесты и сборочные
скрипты разработчика также не запускаются автоматически готовой bit-программой.

Проверка включала поиск вызовов запуска процессов в исходниках компилятора и
четырёх вариантах рантайма, а также запуск с подставными утилитами. На обеих
архитектурах macOS и на Linux под QEMU старый `os >> cpus` вернул подставное
значение `12345`, а `os >> procs` — подставной текст `ps`; на настоящей Windows
`os >> procs` запустил подставной `tasklist`. После исправления `os >> cpus`
сравнивается с системным числом и проверяется ловушкой `getconf`. `os >> procs`
проверяется ловушками для `ps` и `tasklist` и наличием собственного PID.
Отдельно Linux-компилятор проверен с настоящим GNU `as`: исправлены комментарии
ассемблера, которые принимал Zig, но отвергал GNU `as`; самосборка под QEMU сошлась.

Следует проверять вызовы, а не только имена строк в ассемблере: некоторые
строки с именами старых команд остались в рантайме, хотя пути выполнения их
больше не используют. Windows HTTP, например, не вызывает `curl`.
